## P-D2 — Testnet token stubs, tiered. The OQ-15 named list is an anchor, not the inventory.

OQ-15 names svZCHF, sUSDS, ixEDEL, and "the major theme tokens" as stub targets. That list is an **anchor, not the full inventory**: the 26 deployable Miliarium pools (Stage M + N constellation, on-disk `script/pools/configs/`) reference a far wider token set — wstETH / fWSTETH / fWETH / sfrxETH / wOETH / rETH / weETH; USDC / USDT / PYUSD / GHO / scrvUSD / ysyBOLD; WBTC / cbBTC; LINK / AAVE / SKY / MORPHO; the `*on` tokenised equities (QQQX / ETHPLUS / BACON / BLKON); and more. The stub strategy is **tiered** so the population is covered without one bespoke stub per token:

- **Tier A — protocol anchors.** Named, spec-faithful, hand-written stubs that reproduce the real token's interface contract and value-shape: svZCHF, sUSDS, ixEDEL (NAV / DTF shape). Under the same audit-inheritance discipline as the real contracts (OQ-15 implementation note: deterministic, non-upgradeable, well-documented).
- **Tier B — generic ERC-4626.** One `StubERC4626` template (plus an optional waEth-style wrapper variant), instantiated N times via deterministic salts / names. Covers the yield-bearing-wrapper population.
- **Tier C — generic ERC-20.** One `StubERC20` template covering the `*on` equities, the BTC wrappers, the plain stables, and the JPYC / tGBP / fBRZ stand-ins.
- **Tier D — wiring.** `test-stubs/TestnetTokenRegistry.sol` (or a JSON env-map) maps each pool config's literal token slot → its deployed stub address, mirroring the mainnet env-injection convention already used in `DeployIxAetheron`.

**Explicit non-stubs.** **AuMM** deploys as REAL protocol code on testnet (it is the token, never a stub). The Aureum-owned Rate Providers — `ERC4626RateProvider`, `CompositeRateProvider` (`src/rate_provider/`, Stage N) — deploy REAL (not stubs); their `getRate()` reads simply point at the Tier-A / Tier-B stubs. **04 ixViatica / 07 ixCambio stay deferred** (fBRZ / aEURS / JPYC / tGBP stubs are optional, non-blocking for the 26-pool constellation; the E-D17 verified-literal bar is a mainnet concern, not a testnet one). The **Balancer V3 substrate on Hoodi** — Vault + factories + the Router redeploy (D33 / O-D5) — is a workstream-B prerequisite, **not** implied by the stub set; it is the substrate the stubs and the Aureum contracts deploy *onto*.

## P-D7 — Invariant harness IDs (per process-doc §10).

The Stage P Foundry invariant harness encodes these process-doc invariants:

- **INV-1 + INV-6** — total AuMM ever minted ≤ 21,000,000, never exceeded across **all** mint paths (LP emission, bootstrap channel, boost leg); only the one-shot minter mints. The crown-jewel S0 supply property.
- **INV-2** — emission conservation against an **independent** `ReferenceEmission.cumulativeAt(block)`: LP + bootstrap + boost = total, checked against a reference re-implementation, never the contract's own getter (the non-circular check, process-doc §10).
- **INV-3 / S0** — fee-split conservation: the 50/50 split is immutable, the creator fee is zero, every extracted fee reaches der Bodensee (none skimmed, stuck, or rerouted).
- **INV-4 (optional)** — vault solvency (real balances ≥ accounted balances), added only if the Tenderly e2e harness touches real Balancer pools.

**Removed: governance-weight monotonicity is NOT an invariant.** It is not an S0 / INV property — F-02 surfaced that an AuMT (BPT) position split *raises* the summed governance weight by design: the value-weighting raises `(value × time)` to a power below 1 (the F-9 quarter-to-third exponent), which is sub-additive, so splitting one position into two raises the sum. Monotonicity-under-split would therefore be a false invariant; it is not in the §10 catalog and is not harnessed. The **INV-2 harness lands after WH-H** (ideally after the cross-seam pass) — it encodes the channel ↔ distributor split (cross-seam (a)) that the white-hat pass must first characterise, so the harness is written against a characterised surface, not a guessed one.

## P-D12 — F-14 svZCHF-membership fix: hook fail-safe skip (universal) + config-fix the two exception pools (routing completeness).

**Finding.** WH-G.2 F-14 (High, Confirmed; PoC `test/fork/AureumFeeRoutingHook.t.sol::test_Fork_F14_SwapRevertsOnPoolWithoutSvZchf`, `fa1dbbd`): `AureumFeeRoutingHook.onAfterSwap` converts every accrued fee token → svZCHF by swapping on `params.pool` (`_swapExactInFeeTokenToSvZchfViaVault` L487-497, `tokenOut: SV_ZCHF`); the Vault reverts when svZCHF is not a registered token of `params.pool`, reverting the user's swap. svZCHF is a member of 24 of 26 Miliarium pools (the hub-token convention); `02 ixAetheron` (native-4626 LST basket) and `06 ixLibertas` (7-token USD hub) omit it, so every fee-charging swap on those two bricks — settlement-critical liveness.

**Venue wall.** A per-fee-token conversion-venue registry (the first-cut "routing fallback") is infeasible: of the 12 distinct tokens across the two pools, 8 have no svZCHF-liquid venue anywhere in the constellation (scrvUSD / USDC / PYUSD / USDT; sfrxETH / rETH / weETH / wOETH). der Bodensee (`[AuMM, sUSDS, svZCHF]`) serves only the sUSDS leg; governance cannot point the other 8 at any venue.

**Decision (user-adjudicated 2026-07-01) — two-part, sequenced.**

**(1) Hook fail-safe skip — universal backstop, lands first, moves F-14 to Fixed.** A new `mapping(address => bool) public poolHasSvZchf` (appended after the `trustedRouter` slot, preserving the C-D11 / I-D16 / F-09 layout) is set inside `onRegister`'s existing `tokenConfig` loop. `onAfterSwap`, immediately after the D10 recursion-guard early-return, adds `if (!poolHasSvZchf[params.pool]) return (true, params.amountCalculatedRaw);` — a non-svZCHF pool skips the whole collect/convert/route path with no revert. The 50% protocol fee still accrues in the Vault (OQ-1 `onRegister` saturation unchanged) and stays governance-withdrawable via `AureumProtocolFeeController.withdrawProtocolFees`; it is simply not auto-swept to Bodensee. Pool token sets are immutable post-registration (Balancer V3), so the cache never staleness-drifts. This guarantees the no-revert property for every non-svZCHF pool, present and future — fail-safe by construction, independent of deploy config. The F-14 PoC flips to assert the swap succeeds and mints no Bodensee BPT. I13-class fix-forward on `stage-p`; the hook is `stage-d`-tagged — no Stage-D re-tag.

**(2) Config fix — add svZCHF to `02 ixAetheron` + `06 ixLibertas` — routing completeness, follows (1).** Both pools gain svZCHF as a member token so on-pool conversion works for all their fee tokens, restoring full auto-routing. Per-pool weight + Quality-Gate re-derivation (svZCHF weight, trimmed legs, svZCHF's admitted-4626 status for the ≥52% numerator) is locked at the config-fix sub-step; canonical `aumm-site` manifest edits are user-side follow-up. Deferred behind (1) because the fail-safe already resolves the liveness bug; the config fix is routing-completeness, not liveness.

**P-D12 (2) amended — 2026-07-01 — config-fix superseded by the sUSDS deposit-token generalization (user-adjudicated).** Part (2) above proposed adding svZCHF to `02 ixAetheron` + `06 ixLibertas`; superseded before implementation. der Bodensee is `[AuMM, sUSDS, svZCHF]`, so the hook can one-side sUSDS as well as svZCHF into it; and `06 ixLibertas` already holds sUSDS at 14% (an admitted yield core, N-D4 / N-D9), so every ixLibertas fee token can swap → sUSDS on-pool — restoring auto-routing with zero composition change. ## P-D13 — F-16 fix: wire the F-10 efficiency-tournament emission caps (full on-chain enumeration).

**Finding.** WH-H.2a F-16 (Medium; path code-confirmed WH-H.2b / WH-H.3a): the F-D15 cold-start EMA seed (`EMASampler.updateEMA` L138-141) adopts a single un-smoothed `TVL_ORACLE.tvl(pool)` spot, which is flash-manipulable via the pool's own live `balancesLiveScaled18` (`TVLOracle.tvl` L273 / L280, no TWAP); the 60-day maturity + 14-day freshness gates (`EmissionDistributor._gatedTvlEMA` L456-462) age but do not wash the seed (one keep-alive update near maturity decays it ~3.3%). `CCBScore.score` is linear in `tvlEMA` (L24) and the non-Miliarium multiplier is `1e18` (`CCBMultiplier.getMultiplier` L297), so a spiked seed becomes `poolScore` 1:1 and, post-Year-1 (α=1), an uncapped `poolScore / totalScore` emission share. The designed defense — the F-10 efficiency tournament caps (`08_bootstrap.md` §xxiii, `11_formulas.md` F-10) — was deferred wholesale by G-D15b ("deferred to Stage H emission distributor") and never built: the tournament (`GaugeEligibility.computeEpochSnapshot`) is dormant (no on-chain caller — WH-G.2), assigns only a favored-cohort binary (no cap tiers), and nothing in the distributor reads it.

**Root defense (canonical).** F-10 ranks all gauged pools by `efficiency_ratio = (swap_fee_revenue + yield_fee_revenue) / emissions_received` (3-epoch MA — exactly `EfficiencyOracle.efficiencyInputs`) and hard-caps the least efficient regardless of CCB share: bottom 15–10% → 1%, bottom 10–5% → 0.5%, bottom 5% → 0.1% of total protocol emissions; excess redistributes to uncapped pools pro-rata by CCB share (`08_bootstrap.md` L116-125). §xxiii L131 states the intent verbatim — "a pool with large TVL and large CCB share but minimal fees ranks at the bottom … receives at most 0.1% of emissions" — which is F-16: a fake-TVL pool earns ~0 fees → bottom 5% → 0.1% cap.

## P-D16 — F16f implementation: `recordScore` emission-cap clamp (implements P-D13 (4)).

**Context.** P-D13 (4) locks the clamp formula `effective = min(effective_uncapped, (cap_t / (1e18 − cap_t)) × (totalScore − poolScore_old))`. F16f maps it onto `EmissionDistributor.recordScore` internals. No new design — this records the implementation-of-record plus the two edges the formula leaves implicit (§12 ambiguity-gate, notes before code).

**(1) No constructor change.** The distributor already holds `IGaugeRegistry public immutable _gaugeRegistry` (L32 — the `isGaugeApproved` gate); the clamp reads `_gaugeRegistry.poolEmissionCapBps(pool)` through it (F16e delegation). `AureumTime`, `FixedPoint` (`using FixedPoint for uint256`), and `GENESIS_BLOCK` are all already in scope. Zero new imports, storage, or constructor args.

**(2) Insertion point + variable mapping.** The clamp sits between the `oldEffective = poolScore[pool]` capture (L485) and the `totalScore` signed-delta (L486). Mapping: `effective_uncapped` = `effective_new` (the H-D33 step-8 reshape); `poolScore_old` = `oldEffective`; `(totalScore − poolScore_old)` = `totalScore − oldEffective` = `S_other` (no underflow — `totalScore` still includes this pool's `oldEffective` contribution at this point). Clamp body: `capT = capBps × 1e14` (bps → 1e18 fixed-point: 100 bps → 1e16 → 1%); `capLimit = capT.divDown(1e18 − capT).mulDown(totalScore − oldEffective)`; `if (effective_new > capLimit) effective_new = capLimit`. The clamped `effective_new` then flows into the L486 signed-delta, the L487 `poolScore[pool]` write, and the `ScoreUpdated` emit — so `_settlePool` allocates emissions proportional to the clamped score. F12/F13 signed-delta discipline unchanged (the clamp only lowers `effective_new` before the existing `_applySignedDelta`).

**(3) Month-13 gate.** The clamp is gated `block.number >= AureumTime.year1EndBlock(GENESIS_BLOCK) + 1` — identical to `GaugeRegistry.advanceTournament`'s gate (P-D14 (3)); the distributor's `GENESIS_BLOCK` MUST equal `GaugeRegistry`'s per the P-D14 (1) deploy invariant so both switch on the same block. No-op below the gate, and a no-op whenever `capBps == 0` (uncapped top-85% pools + all pools pre-tournament).

**(4) Rounding + the `S_other == 0` degenerate.** `divDown` then `mulDown` both round down, so `capLimit` rounds down — the capped pool's share lands at-or-slightly-below `cap_t` (protocol-conservative, anti-attacker). Degenerate `S_other == 0` (the capped pool is the sole scorer) → `capLimit == 0` → `effective_new → 0`: unreachable when caps are active (a non-zero `capBps` requires `nRanked ≥ 20` in the tournament per P-D15 (1) → ≥ 20 scored pools → `S_other > 0`) and safe (halts emission to a lone capped pool rather than paying it uncapped). No special-case guard added. `1e18 − capT` is always positive (`capT ≤ 1e16`), so no divide-by-zero.

**(5) Multi-cap convergence + test posture.** The clamp reads the live `totalScore`, so under k simultaneous caps successive `recordScore` sweeps converge toward the exact `e_i = cap_i · U / (1 − Σcap_j)` system with the O(cap^2) per-pass coupling P-D13 (4) notes (≤ ~1e-4 at 0.1–1% caps) — no bit-exact assertion. F16f is additive: existing `recordScore` tests stay green (clamp is a no-op pre-month-13 and the F16e-b `EmissionDistributor.t.sol` mock returns `capBps == 0`). Comprehensive cap-clamp coverage is F16g, which must first make that mock's `poolEmissionCapBps` settable.

**Decomposition.** F16f-pre P-D16 lock (this) → F16f `EmissionDistributor.recordScore` clamp (source, additive — existing tests green) → F16g unit tests (cap clamp + `advanceTournament` coverage, settable mock) → F16h F-16 fork PoC per P-D13.
