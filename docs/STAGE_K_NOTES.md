### K-D3 — `AureumGovernanceAuthorizer` design per OQ-10 — status LOCKED

Locked at the K1 pre-flight Opus beat (OQ-10 FINDINGS L722-794 + the Stage B `AureumAuthorizer` migration-target + Balancer `IAuthorizer` + a submodule probe of the action-ID encoding). The contract is the B-strict authorizer with a 12-month emergency window: after the Stage B multisig signs the one-shot `Vault.setAuthorizer`, `GOVERNANCE_CONTRACT` becomes primary and `EMERGENCY_MULTISIG` keeps a narrow, time-boxed emergency role that dies permanently at `EMERGENCY_WINDOW_END_BLOCK`.

**Shell + interface.** `contract AureumGovernanceAuthorizer is IAuthorizer` (`pragma ^0.8.26`, same `@balancer-labs/v3-interfaces` import as the Stage B `AureumAuthorizer`). No new Aureum interface file: the external surface is the single `IAuthorizer.canPerform` plus the auto-generated public-immutable getters, exactly as the interface-less Stage B authorizer. SCREAMING_CASE immutables carry the `slither-disable-next-line naming-convention` rationale comment from `AureumAuthorizer.sol`.

**State.** Three immutables — `GOVERNANCE_CONTRACT`, `EMERGENCY_MULTISIG`, `EMERGENCY_WINDOW_END_BLOCK` — plus two `bytes32` immutable emergency action IDs (`EMERGENCY_ACTION_PAUSE_VAULT`, `EMERGENCY_ACTION_ENABLE_RECOVERY_MODE`) and one constant `EMERGENCY_WINDOW_BLOCKS = 2_628_000` (= 12 × `BLOCKS_PER_MONTH` = `BLOCKS_PER_YEAR`; OQ-3 / OQ-10).

**Constructor `(address governanceContract_, address emergencyMultisig_, address vault_)`.** Reverts on a zero value for any of the three. Sets `EMERGENCY_WINDOW_END_BLOCK = block.number + EMERGENCY_WINDOW_BLOCKS` — the window is measured from the authorizer's own construction block, which is the migration block to within the deploy→`setAuthorizer` gap (immaterial against 2.6M blocks; OQ-10 steps 2-3). Computes the two action IDs locally with no external call (H13-safe, mirroring the J-D4 H13-safe constructor), importing `IVaultAdmin` for the selectors: `keccak256(abi.encodePacked(bytes32(uint256(uint160(vault_))), IVaultAdmin.pauseVault.selector))` and the same for `enableRecoveryMode`. `vault_` is a constructor argument rather than a hardcoded constant so unit tests can supply a test address and compute the expected IDs identically; the K7 deploy passes the locked mainnet Vault `0xbA1333333333a1BA1108E8412f11850A5C319bA9` and the K7 fork test confirms the real Vault's `getActionId` agrees.

**Action-ID encoding (submodule-verified).** Balancer's `Authentication.getActionId(selector) = keccak256(abi.encodePacked(_actionIdDisambiguator, selector))` (`Authentication.sol:51`), and `VaultAdmin` sets `_actionIdDisambiguator = bytes32(uint256(uint160(address(mainVault))))` (`VaultAdmin.sol:77`) — the disambiguator is the Vault address, not VaultAdmin's, so the authorizer needs `vault_` to reproduce the IDs. The `pauseVault()` and `enableRecoveryMode(address)` selectors live on `IVaultAdmin` (L136 / L241).

**Emergency-action set = {`pauseVault`, `enableRecoveryMode`}** (user decision 2026-06-07). The two direct damage-halting levers — global halt and per-pool safe-exit without a global pause. `disableQuery` (OQ-10's third candidate) is dropped: it is permanent defensive-config, not crisis-response, and keeping the deprecated multisig's residual surface minimal honors the constitutional "no multisig" framing. `_isEmergencyAction(actionId)` returns `actionId == EMERGENCY_ACTION_PAUSE_VAULT || actionId == EMERGENCY_ACTION_ENABLE_RECOVERY_MODE`.

**`canPerform(bytes32 actionId, address account, address /* where */)`.** `account == GOVERNANCE_CONTRACT` → `true` (governance does anything authorizer-gated); `account == EMERGENCY_MULTISIG && _isEmergencyAction(actionId) && block.number < EMERGENCY_WINDOW_END_BLOCK` → `true`; otherwise `false`. `where` is ignored (governance authority is global, matching OQ-10's `/* target */`). The window boundary is strict: at `block.number == EMERGENCY_WINDOW_END_BLOCK` the emergency clause is already dead.

### K-D4 — TVL-oracle binding for vote-weighting — status LOCKED

Locked at the K2 pre-flight Opus beat (reading `src/ccb/ITVLOracle.sol` + `src/emission/TVLOracle.sol`). The binding is **reuse-direct**: no new K2 contract and no adapter.

**What K3 needs.** Per I-D14, AuMT is the gauged pool's own Balancer V3 BPT, so a holder's "AuMT value" is the svZCHF value of their BPT position: `holderValue = tvl(pool) × balanceOf(holder) / totalSupply()`, where `balanceOf` / `totalSupply` are read directly off the pool/BPT (no oracle) and `tvl(pool)` is the only oracle dependency. The qualification gates (14-day cliff, 6-month on-ramp, gauged-only, the `^(1/4 → 1/3)` curve) are `VotingWeight`'s own logic per K-D5, layered on top of this raw value — out of scope for K-D4.

**Why reuse-direct.** `ITVLOracle` already exposes `tvl(address pool) external view returns (uint256)` (svZCHF, 18-dec; `src/ccb/ITVLOracle.sol` L14), and `TVLOracle` implements it (`src/emission/TVLOracle.sol` L211). That is precisely the whole-pool valuation `VotingWeight` multiplies by BPT share — so `VotingWeight` takes an `ITVLOracle` constructor immutable and calls `oracle.tvl(pool)`. No new interface, no adapter, no per-holder oracle method (share math is `VotingWeight`'s). `quoteSvZCHF` (the per-token H-stage entry) is not used by governance. K2 therefore produces **no code surface** — the oracle consumption folds into the K3 `VotingWeight` constructor.

**Single shared instance.** "Reuse" means the same deployed `TVLOracle` the emission `EfficiencyOracle` path reads — one constellation roster, one `tokenToUnderlying` map, one `setGovernanceContract` (H-D8) handoff migrating it to governance at Stage K. A separate governance-local oracle would double the roster-maintenance burden with no isolation benefit. The exact deploy ordering (deployed inside `DeployStageK.s.sol` vs. already-live and passed as a K7 Stage-input like AuMM per H-D42) is fixed at K-D9; K-D4 commits only to the single-instance design intent.

**K6 interaction is signature-stable.** K6 (K-D8) re-points `TVLOracle._constellationRatio` to enumerate the live `MiliariumRegistry` dense view — an internal valuation-accuracy change that does not alter `tvl`'s ABI. `VotingWeight`'s binding to `ITVLOracle.tvl` therefore survives the K6 re-wire unchanged; only the accuracy of the returned svZCHF figure improves as the roster densifies. Pre-K6, `tvl()` runs on the F-D9 placeholder roster (Bodensee + governance-added pools); gauged Miliarium pools value correctly once K6 lands.

**K2 sub-steps.** K2.0a (this NOTES lock) → K2.0b (PLAN K-D4 mirror flip + K2 roadmap marked documentation-only + Completion Log). No K2.1 / K2.2 — there is no K2 code surface; the `ITVLOracle` injection is a K3 (`VotingWeight` constructor) concern.

### K-D5 — `VotingWeight` value-weighted reader = stateful poke-accumulator — status LOCKED

Locked at the K3 pre-flight Opus beat (F-9 `11_formulas.md` + `04_tokenomics.md` §viii + OQ-25 FINDINGS L1302-1318 + the EmissionDistributor recorder clock + `IMiliariumRegistry` enumeration + `FixedPoint.powDown`). Resolves the I-D17 deferred `totalSupply()` denominator semantic. Two forks went to the user (2026-06-08): (1) denominator model — **stateful exact sum** chosen over the stateless proxy and the value proxy; (2) the realizability collision — F-9's concave root blocks the veCRV-style linear aggregation that would make an exact live total cheap (any two of {exact fraction, live per-block time-growth, no holder enumeration} are achievable, not all three), resolved as the **stateful poke-accumulator** rather than reverting to the stateless live proxy.

**The exact-fraction invariant.** Both reader functions return *checkpointed* state, so `vetoSupport ≤ totalSupply` holds by construction with no live/checkpoint mismatch. `governanceWeight(holder)` returns the stored `_holderWeight[holder]` (the sum of that holder's checkpointed per-pool powers); `totalSupply()` returns `_totalQualifiedWeight` (the running Σ of every holder's checkpoint). Each holder's checkpoint is a summand of the total and distinct voters hold disjoint positions, so `vetoSupport / totalSupply ∈ [0, 1]` always — the true 0—100% veto fraction `VaultClassRegistry.vetoProposal` (L277-L279) assumes. Both functions stay `view`, so the I-D17 `IVotingWeight` interface (`governanceWeight(address) → uint256` + `totalSupply() → uint256`, both `view`) is honored without a breach; `poke` is a concrete-only method, not part of the interface.

**State — two slots.** `mapping(address => uint256) _holderWeight` and `uint256 _totalQualifiedWeight`. No per-position storage — a poke recomputes the holder's whole aggregate live and applies a single signed delta to both slots; `governanceWeight` and `totalSupply` only ever read the two aggregates.

**`poke(address holder)` — permissionless, mutating.** Recomputes `newAgg = Σ` of `_positionPower(pool, holder)` over the gauge-filtered registry enumeration (≤ 28 pools), then applies `delta = int256(newAgg) − int256(_holderWeight[holder])` to both `_holderWeight[holder]` and `_totalQualifiedWeight` via the F12/F13 signed-add discipline (delta as `int256`, branch on sign, cast back after — `delta` is negative when a position's weight drops, e.g. on withdrawal-reset). Permissionless by design: anyone can refresh any holder, including resetting a *withdrawn* holder's stale checkpoint to its live zero — so the withdrawal-reset rule (§viii "remove any amount — even 1% — governance power drops to zero") is enforceable by any honest observer, not only the holder. K4 `AureumGovernance` calls `poke(msg.sender)` at its vote entry (the snapshot-fresh main path); the Stage-G `VaultClassRegistry` veto path is left byte-stable and reads the voter's last-checkpoint weight (a manual or third-party `poke` refreshes it).

**Per-position power `_positionPower(pool, holder)` (internal, live).** (a) gauge gate: `!GAUGE_REGISTRY.isGaugeApproved(pool)` → 0 (read-time per OQ-7 / OQ-25; the clock accrues independent of gauge status); (b) clock: `eqb = RECORDER.effectiveQualBlock(pool, holder)`; `eqb == 0` → 0 (no position or withdrawn-reset); `time = block.number − eqb`; `time < QUALIFICATION_PERIOD_BLOCKS` → 0 (14-day cliff); `cappedTime = min(time, ON_RAMP_PERIOD_BLOCKS)`; (c) value: the recorder share below; (d) root: `base = value.mulDown(cappedTime × 1e18 / ON_RAMP_PERIOD_BLOCKS)`; `exp = block.number < AureumTime.firstHalvingBlock(GENESIS_BLOCK) ? 0.25e18 : ONE/3`; `power = base.powDown(exp)`.

**Value term — recorder share per OQ-25; supersedes the K-D4 `balanceOf` shorthand.** `value = ORACLE.tvl(pool) × RECORDER.userLP(pool, holder) / RECORDER.poolTotalLP(pool)`. **Staleness semantics.** Checkpoint staleness is *mostly* conservative for threshold dynamics: an unpoked dormant holder under-counts the denominator's time-growth, making a veto *harder* to reach. The exception is **withdrawal without poke** — a withdrawn holder's `_holderWeight` stays stale-high until someone calls `poke(holder)`, overstating that one holder's checkpoint (though `vetoSupport / totalSupply ≤ 1` still holds because both slots move together on every poke). The mitigation is the permissionless poke: opponents should `poke` contested holders before a contested veto. This is a feature, not an accident — logged for the Stage-P security pass.

**ON_RAMP normalization cancels in ratios.** `base = value.mulDown(cappedTime × 1e18 / ON_RAMP_PERIOD_BLOCKS)` then `powDown(exp)` is *not* byte-identical to `(value × cappedTime)^exp` in absolute units — it carries a uniform `(1 / ON_RAMP_PERIOD_BLOCKS)^exp` factor, identical across every position, so it cancels in every ratio the protocol uses (veto bps, holder-vs-holder weight). The normalization keeps the `powDown` base in svZCHF magnitude (bounded by pool TVL × a fraction ≤ 1), well inside the `LogExpMath` domain. Auditors should not chase absolute `governanceWeight` numbers against the prose spec — only ratios are load-bearing.

**K11 — Foundry `vm.expectRevert(bytes4 selector)` does not prefix-match a parameterized custom error; parameterized reverts need `abi.encodeWithSelector(selector, params)` (K4.6b unit cohort).** Surfaced at K4.6b: the `bytes4`-selector overload of `expectRevert` matches only when the actual revert payload is exactly four bytes — a parameterless error. A custom error that carries an ABI-encoded argument reverts with the four selector bytes plus a 32-byte word per parameter, so the `bytes4` expectation fails on the full-payload comparison — it is an exact match, not a four-byte prefix match. Empirical signature at the K4.6b first run: all parameterless-error assertions passed (`ZeroAddress`, `InvalidPayToken`), and all seven parameterized-error assertions failed with `Error != expected error: <Name>(<param>) != custom error 0x…` across `InvalidGaugeTarget(address)`, `InvalidCompositionTarget(uint256)`, `InvalidFeeTarget(address)`, and `InvalidFeeValue(uint256)`. Fix: a parameterized custom error uses `vm.expectRevert(abi.encodeWithSelector(AureumGovernance.<Error>.selector, <exactParam>))`, which exact-matches the full revert payload and additionally asserts the offending value the error reports; parameterless errors stay on the bare `.selector` form. The forge-std ≥ 1.15.0 `vm.expectPartialRevert(bytes4)` would match the selector only and ignore the parameter, but the encoded form is strictly stronger and version-independent — adopt it as the K4.6-onward default. Param typing: cast integer literals to the error's declared width (`uint256(0)`, `uint256(29)`, `uint256(1e14 - 1)`); pass address parameters through directly. **K12 — The optimizer reuses a CSE'd `block.number` across sequential `vm.roll` calls in a straight-line fork test; roll to a stored absolute field, not a re-read `block.number` (K4.7c composition-lifecycle, F10 extension).** Surfaced at K4.7c: a multi-roll governance-lifecycle fork test — deposit → `vm.roll(block.number + QUALIFICATION_PERIOD_BLOCKS + 1)` (clear the cliff) → propose → `castVote` → `vm.roll(block.number + BLOCKS_PER_EPOCH + 1)` (close the voting window) — left `gov.state(id)` stuck at `Active`, failing `succeeded: 0 != 2`, although the arithmetic placed `block.number` one block past the proposal's `endBlock`.
