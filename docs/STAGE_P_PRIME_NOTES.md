## PP-D9 — The G.3 fix carries a mandatory companion: an execute-time `slotOf(p.targetPool) == 0` re-check on the `GaugeChallenge` branch

The refuted hypothesis "a Miliarium pool can be gauge-challenged out" (`PROGRESS.md` "refuted hypotheses") is refuted only by an undocumented cross-contract coupling: `proposeGaugeChallenge` checks `slotOf(targetPool_) == 0` at propose time only (`src/governance/AureumGovernance.sol` L229), and that premise cannot be falsified today because the only reachable `replaceSlot` caller, the composition branch (L432), immediately calls `registerGaugeFromComposition` (L433), which rejects an `Active` pool (`src/gauge/GaugeRegistry.sol` L170). A pool that was `Active` at a gauge challenge's propose time can therefore never become a Miliarium member before that challenge executes. The natural fix to `composition-challenge-bricked-by-permissionless-gauge-activation` — let the composition branch TOLERATE an already-`Active` candidate, so a 100-svZCHF `activateGauge` cannot poison it — makes an `Active` pool seatable, falsifies the premise, and lets a banked simple-majority `GaugeChallenge` terminally revoke a Miliarium pool, bypassing the 2/3 bar the constitution requires for any structural change to the 28. Lock: the tolerate change and the `GaugeChallenge` re-check at L426-427 land in ONE rung (PP4 rung 9, with G.2's incumbent freeze over the same six lines per PP-D30), with a comment at both sites naming the coupling, and a regression that banks a gauge challenge against an `Active` unslotted pool, seats that pool by composition, and asserts the banked challenge reverts at execute. This is the first of the twenty constraints and the template for the rest: a fix is not done until the thing that was relying on the defect is named.
